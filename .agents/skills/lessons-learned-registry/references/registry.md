# Lessons Learned Invariants Registry

- **L-001** | Feed deletion cascades to products; counters decrement atomically | Backend, SQLite, mock | E2E: after feed deletion, product count and `products_count` decrement.
- **L-002** | Mock/SQLite and production server return identical hydrated fields (`supplierName`, `categories`, `activeFeedsCount`) | `mockDatabaseDriver`, `LocalProductsService` | Unified parity test suite across mock and cloud modes.
- **L-003** | Table cells must never render column headers as data values (e.g. `Supplier`) | Desktop UI products table | Negative assertion: `expect(text).not.toBe('Supplier')`.
- **L-004** | Tests assert concrete business entities, not mere DOM presence | Playwright automation | Review: presence of `expect` assertions on business data.
- **L-005** | Only `@/` path alias and `@smartfeed/shared` imports; zero relative `../` or `./` across packages | All monorepo packages | ESLint `no-restricted-imports`.
- **L-006** | Feed URLs must not be hardcoded to real vendor domains in DTOs and tests | `fetch-feed-url.dto.ts`, handler specs | Use neutral domains like `https://example.com/feed.xml`.
- **L-007** | Feed URLs must support re-fetching and price/stock synchronization | Feed import pipeline | E2E test verifying updates via URL fetch.
- **L-008** | Product and category counters update synchronously after import or deletion | Admin and desktop clients | Assertion: counter equals exact database count.
- **L-009** | Adaptive typography strictly consumes semantic design tokens; zero ad-hoc pixel values | UI components | Automated invariant check against design tokens.
- **L-010** | CQRS modularity: 1 file = 1 CommandHandler; monolithic multi-handler files prohibited | `services/backend-api` | Structural check: each handler file <120 lines.
- **L-011** | Zero raw query parameters: all `@Query()` parameters in NestJS require validated DTOs | Controllers (`users`, `payments`, `suppliers`) | Validation rejects unvalidated or negative parameters.
- **L-012** | Zero headless desktop spawns: prohibit `open` or `explorer` OS calls in cloud NestJS API | Cloud storage, workspace disk | Structural audit: no OS GUI execution in backend API.
- **L-013** | Table row extraction: shadcn DataTable with >3 columns must extract row rendering to `*TableRow.tsx` | Desktop and Admin Portal | File size check: `*DataTable.tsx` <180 lines, row extracted.
- **L-014** | List page modularity: list pages extract modals to `*DialogsContainer.tsx` and state to `use*PageState` | `SuppliersListPage.tsx`, list views | File budget: view <200 lines, state isolated in hook.
- **L-015** | OWASP API4: prohibit direct `select-plan` upgrades for paid plans without valid `transactionId` | `licenses`, `select-tariff-plan.handler.ts` | Verification: unpaid upgrade requests return 402/403.
- **L-016** | Secret masking: `merchantSecretKey` and provider tokens must be masked in `GET /settings` responses | Payment settings handler | Verification: response returns masked string `••••••••`.
- **L-017** | SSRF TOCTOU: DNS lookup and `fetch()` must share pinned IP address to prevent DNS rebinding | Feed fetch handler | IP pinning assertion prevents DNS rebinding with TTL=0.
- **L-018** | 100% protected mutation endpoints: all POST/PUT/DELETE/PATCH routes require `@UseGuards(JwtAuthGuard)` or explicit `@Public()` | All NestJS controllers | Security test: unauthenticated mutation returns 401/403.
- **L-019** | Zero hardcoded fallback secrets (CWE-798): prohibit `|| 'fallback-secret'` for tokens and keys | Auth services, strategy, webhooks | Missing environment variable throws 500 or halts bootstrap.
- **L-020** | Guard-decorator parity: `@CurrentUser()` usage in controllers requires `@UseGuards(JwtAuthGuard)` | Controller methods | Request pipeline hydrator test confirms `request.user`.
- **L-021** | Strict native vs cloud runtime segregation: prohibit local desktop filesystem operations on cloud server | Cloud storage controllers | Architecture review: zero desktop FS calls in NestJS.
- **L-022** | Mandatory `@db.Timestamptz(6)`: all `DateTime` fields in `schema.prisma` must specify `@db.Timestamptz(6)` | `schema.prisma` | Schema audit: 0 unannotated DateTime fields.
- **L-023** | Zero silent failures in backend: empty or comment-only `catch` blocks prohibited | Backend services and handlers | Linter/audit: 0 empty catch blocks.
- **L-024** | Zero fake stubs and zero `as any` in production controllers; background jobs use BullMQ | Feeds controller | Static check: 0 `as any` in controllers.
- **L-025** | Prisma zero N+1 and cursor pagination: prohibit `findUnique` inside loops; catalogs require cursor pagination | Prisma repositories and handlers | Code review: 0 queries in loops, cursor pagination enabled.
- **L-026** | Prisma versioned expand/contract migrations: prohibit unversioned `prisma db push` in production | Database migrations | CI gate: migrations present in `prisma/migrations`.
- **L-027** | Strict Prisma types and short `$transaction()`: prohibit `as any`; transactions must not wrap S3/email/HTTP/BullMQ | Handlers and services | Review: short database-only transactions.
- **L-028** | Zero server desktop workspace FS ops (DEF-01): prohibit `fs.mkdirSync` for local desktop catalogs on server | Cloud storage modules | Architecture audit: zero desktop workspace operations.
- **L-029** | Zero hardcoded fallback secrets (DEF-02): prohibit database connection string fallbacks | Database service | Missing `DATABASE_URL` halts application bootstrap.
- **L-030** | Guaranteed password reset flow (DEF-03): reset token generation must dispatch email via MailService | Auth and mail services | Integration test confirms dispatch of password reset email.
- **L-031** | Short-lived access tokens (DEF-04): default JWT access token TTL must not exceed 15-30 minutes | Token service | Configuration test: `JWT_ACCESS_EXPIRATION` <= 15m.
- **L-032** | Redis distributed mutex (DEF-05): prohibit in-memory locks for quota guards across horizontal replicas | Organization mutex helper | Review: distributed lock via Redis `SET lock NX PX 15000`.
- **L-033** | Layer-2 quota & AI credits (DEF-06): supplier creation and AI requests must check license limits and deduct credits | Supplier handler, LLM gateway | Integration test: quota exceeded returns 403.
- **L-034** | Anti-BOLA organization isolation (DEF-07): supplier queries and mutations must filter by `organizationId` | Suppliers controller | Integration test: organization members access shared data.
- **L-035** | HTTPS IP pinning & SSRF TOCTOU (DEF-08): DNS rebinding defense extends across both `http:` and `https:` via custom agent | Feed fetch handler | Verification: IP pinning active on HTTPS requests.
- **L-036** | Database field encryption (DEF-09): merchant secret keys and feed tokens encrypted with AES-256-GCM before DB write | Schema and payment storage | Assertion: ciphertext stored in database, not raw secret.
- **L-037** | Tight 2MB body limit anti-OOM (DEF-10): prohibit global 100MB body limits; large uploads go through S3 presigned URLs | `main.ts` | Server bootstrap audit: body limit <= 2MB.
- **L-038** | Mandatory hierarchy FK indexes (DEF-11): self-referencing and parent entity relations require `@@index([fk])` | `schema.prisma` | Schema audit: 0 foreign keys without index.
- **L-039** | Zero N+1 deletes in loops (DEF-12): prohibit individual `prisma.delete()` calls in worker loops | Storage GC processor | Batch deletion check: `deleteMany({ where: { id: { in: ids } } })`.
- **L-040** | Cursor pagination over offset (DEF-13): high-volume lists (>10k) require cursor pagination (`cursor: { id }`) | Storage handlers | Schema query audit: cursor pagination supported.
- **L-041** | Real BullMQ queue jobs (DEF-14): prohibit static mock responses; background import dispatches real BullMQ job | Feeds controller | Integration test: `importAsync` enqueues job in BullMQ.
- **L-042** | Atomic payment webhooks (DEF-15): status transition to `APPROVED` and license activation execute in single `$transaction` | WayForPay webhook handler | Integration test: failure rolls back payment status.
- **L-043** | Strict CQRS contracts (DEF-16): CommandHandler returns strictly `{ id }` or `void`; controllers delegate to buses | Organization and legal handlers | Architecture check: controllers route through buses.
- **L-044** | Error sanitization & clean logs (DEF-17): exception filter masks Prisma internal error codes in production; no emojis in logs | Exception filter, `main.ts` | Clean ASCII logs, 0 internal database codes exposed.
