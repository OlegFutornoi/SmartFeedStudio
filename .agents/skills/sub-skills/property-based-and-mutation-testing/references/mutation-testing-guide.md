# Mutation Testing Guide — Мутаційне тестування зі Stryker

## 1. Що таке Mutation Score?

Мутаційне тестування оцінює якість самих тестів, вносячи штучні помилки (мутації) у робочий код:

- **Killed (Вбитий)**: Тести впали після внесення мутації -> ✅ Тест якісний.
- **Survived (Вижив)**: Код зіпсовано, але тести все одно пройшли -> ❌ Тест фіктивний, не перевіряє поведінку.
- **Mutation Score**: Відсоток убитих мутантів (цільовий показник для ядра парсерів та CQRS: >80%).

## 2. Типові мутатори, які ловлять дефекти

1. **EqualityOperator**: Заміна `>` на `>=`, `===` на `!==`. Ловить помилки граничних значень пагінації та квот.
2. **BlockStatement**: Очищення тіла функції або методу каскадного видалення. Якщо після видалення логіки тест зелений — тест не перевіряє базу даних.
3. **BooleanLiteral**: Заміна `true` на `false` у фільтрах наявності чи активності фідів.
4. **ArrayDeclaration**: Заміна масиву результатів на пустий `[]`.

## 3. Конфігурація Stryker для модуля парсерів

```json
{
  "$schema": "./node_modules/@stryker-mutator/core/schema/stryker-schema.json",
  "packageManager": "pnpm",
  "testRunner": "jest",
  "mutate": ["services/backend-api/src/modules/feeds/parsers/**/*.ts", "!**/*.spec.ts"],
  "thresholds": { "high": 85, "low": 75, "break": 70 }
}
```
