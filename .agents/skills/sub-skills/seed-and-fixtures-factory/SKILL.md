# 🏭 Seed & Fixtures Factory — Фабрики тестових даних та автоочищення

> **Призначення:** Стандартизована генерація тестових даних для E2E/інтеграційних тестів та дев-середовища: XML/CSV фіди постачальників будь-якого розміру, зв'язані сутності БД (User, Org, License, Supplier, Feed, Product), та залізний авто-teardown без осиротілих рядків.

## 🏛 Залізні інваріанти фабрик даних

1. **100% Teardown (Zero Leftovers)**:
   - Кожен тест, що створює фікстури в PostgreSQL чи SQLite, зобов'язаний викликати `cleanDatabase` у `beforeAll` та `afterAll`.
   - Жоден запис не повинен залишатися в базі після прогону сьюту.
2. **Deterministic Data (No Random Magic)**:
   - Використовувати детерміновані префікси: `test_e2e_*`, фіксовані seed для faker, або лічильники послідовностей (`seq++`).
   - Усуває конфлікти унікальних ключів (`email`, `licenseKey`, `slug`).
3. **Defense-in-Depth Validation у фабриках**:
   - Фікстури створюються через спільні DTO контракти `@smartfeed/shared`.
   - Заборонено генерувати невалідні об'єкти, які суперечать Zod-схемам (якщо це не спеціальний тест валідації).
4. **100% Data Parity**:
   - Фабрики для `mockDatabaseDriver` (браузер) і серверні фікстури Prisma повертають **однакові поля та зв'язки**.

## 📋 Чеклист використання перед запуском тестів

- [ ] Використано канонічний хелпер `cleanDatabase()` у `afterAll()`
- [ ] Усі тестові користувачі мають префікс `test_e2e_` для безпечного селективного видалення
- [ ] Зв'язки між сутностями (Org -> Member -> License) створюються у коректній послідовності FK
- [ ] Великі файли фідів (10k+ SKU) створюються у тимчасовій директорії `os.tmpdir()` та видаляються після тесту
