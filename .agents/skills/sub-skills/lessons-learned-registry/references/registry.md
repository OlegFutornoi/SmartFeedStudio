# Registry — виправлені класи помилок (інваріанти)

| #     | Інваріант                                                                                                              | Де проявилось                                | Перевірка                                                              |
| ----- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------- |
| L-001 | Видалення фіда каскадно видаляє його товари; лічильники зменшуються атомарно                                           | backend + SQLite + mock                      | E2E: після delete feed кількість товарів і `products_count` зменшились |
| L-002 | Mock/SQLite і реальний сервер повертають ідентичні гідратовані дані (`supplierName`, `categories`, `activeFeedsCount`) | `mockDatabaseDriver`, `LocalProductsService` | Один тест-сьют на обидва режими                                        |
| L-003 | Колонка таблиці ніколи не показує назву колонки як значення (напр. «Постачальник»)                                     | UI таблиця товарів                           | `expect(text).not.toBe('Постачальник')` + реальна назва                |
| L-004 | Тести перевіряють бізнес-дані, а не «сторінка відрендерилась»                                                          | Playwright                                   | Ревʼю: наявність `expect` на реальні сутності                          |
| L-005 | Лише імпорти `@/` та `@smartfeed/shared`; жодного `../` і `./`                                                         | всі пакети                                   | ESLint `no-restricted-imports`                                         |
| L-006 | URL фідів не хардкодяться в DTO/тестах (приклади реальних постачальників)                                              | `fetch-feed-url.dto.ts`, handler spec        | Нейтральні `https://example.com/feed.xml`                              |
| L-007 | URL фіда має бути відкриваним/оновлюваним (залишки та ціни оновлюються за посиланням)                                  | імпорт фідів                                 | E2E повторного оновлення за URL                                        |
| L-008 | Лічильники (товари, категорії) в клієнті з сервером оновлюються після імпорту/видалення                                | admin/desktop                                | Тест: лічильник = реальна кількість                                    |
| L-009 | Адаптивні розміри шрифтів з дизайн-токенів, без випадкових розмірів                                                    | UI                                           | Visual/ревʼю по токенах                                                |
