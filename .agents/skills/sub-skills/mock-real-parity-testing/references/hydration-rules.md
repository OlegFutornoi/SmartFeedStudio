# Hydration Rules — Правила гідратації зв'язків у локальних драйверах

## 1. Проблема розриву даних

Часта помилка: на бекенді виконується `include: { supplier: true, category: true }`, а в `mockDatabaseDriver` або локальному SQLCipher повертаються лише сирі зовнішні ключі (`supplier_id`), через що UI показує порожні місця або технічні заглушки (як-от слово "Постачальник").

## 2. Залізні правила гідратації

1. **Завжди заповнювати зв'язані сутності**:
   ```typescript
   // Правильно в MockDriver:
   const product = {
     id: 'prod_1',
     title: 'Смартфон XYZ',
     supplierId: 'sup_1',
     supplierName: 'Brain Distribution', // ОБОВ'ЯЗКОВО!
     categoryName: 'Смартфони', // ОБОВ'ЯЗКОВО!
     activeFeedsCount: 3,
   };
   ```
2. **Нуль хардкоду заглушок**: Заборонено рендерити `t('supplier')` чи `"Постачальник"` у комірці значення товару, якщо `supplierName` відсутній. Повинна показуватися або реальна назва, або локалізоване `—` (тире).
3. **Синхронізація лічильників**: Якщо мок-база оновлює товар, вона зобов'язана перерахувати агрегати по постачальнику так само, як це робить тригер або сервіс на бекенді.
