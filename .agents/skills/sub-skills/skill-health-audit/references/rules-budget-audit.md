# 📏 Rules Budget Audit — Контроль ліміту 12k символів для .agents/rules/

## 1. Чому діє жорсткий ліміт 12,000 символів

Система налаштувань Antigravity IDE має апаратне обмеження на розмір одного rule-файлу (12,000 символів). Якщо файл перевищує цей ліміт:

- Частина правил обрізається під час завантаження в системний промпт.
- Агент перестає бачити критичні інваріанти або отримує помилку парсингу конфігурації.

---

## 2. Команда швидкої діагностики розмірів правил

```bash
# Перевірка кількості символів у всіх правилах
for f in .agents/rules/*.md; do wc -m "$f"; done
```

| Рівень тривоги              | Кількість символів | Дія                                                                                  |
| :-------------------------- | :----------------- | :----------------------------------------------------------------------------------- |
| **Норма**                   | < 10,000           | Змін не потрібно                                                                     |
| **Жовта зона (Warning)**    | 10,000 – 11,500    | Заборонено додавати нові секції без скорочення                                       |
| **Червона зона (Critical)** | ≥ 11,500           | Негайна декомпозиція: винесення блоків у новий `rule-*.md` або скорочення дублікатів |

---

## 3. Алгоритм декомпозиції правил при наближенні до ліміту

1. Знайти в `.agents/rules/` файл, що досяг 11,000+ символів (наприклад, `code_review_and_skills.md`).
2. Визначити логічно відокремлюваний блок (наприклад, детальний опис інструментів чи чеклисти).
3. Створити новий файл у `.agents/rules/<new_name>.md` (до 8,000 символів).
4. Зареєструвати новий файл в індексі `AGENTS.md` (розділ `🏛 Rules Index`).
5. Переконатися, що обидва файли валідні, лаконічні та < 10,000 символів.
