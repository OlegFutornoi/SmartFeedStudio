# 🩺 Skill Health Audit — Аудит та очищення екосистеми скілів

> **Призначення:** Систематичний аудит 80+ скілів монорепозиторію: ліквідація дублікатів, виправлення одруків у назвах каталогів, верифікація цілісності символічних посилань у `.claude/skills/`, контроль модульності `lark-shared` (SKILL.md ≤150 рядків + references/) та дотримання ліміту символів у `.agents/rules/*.md`.

## 🏛 4 Залізні стандарти здоров'я екосистеми

1. **Єдиний канонічний скіл для одного поняття (Zero Duplicates)**:
   - Не може існувати двох скілів з однаковим призначенням (наприклад, `test-driven-development` та `test-driven-development-tdd`, або `frontend-desing` та `frontend-design`).
   - Один зливається в канонічний, дублікат вилучається разом із застарілим симлінком.
2. **100% Валідні символічні посилання (Zero Broken Symlinks)**:
   - Кожен підскіл у `.agents/skills/sub-skills/<name>` повинен мати валідний відносний симлінк у `.claude/skills/<name>`.
   - Жодного «мертвого» або циклічного посилання.
3. **Стандарт `lark-shared` для всіх нових/оновлених скілів**:
   - Головний `SKILL.md` ≤ 150 рядків: YAML frontmatter, призначення, таблиця тригерів, ключові інваріанти.
   - Детальні приклади коду, гайди та інструкції виносяться в папку `references/`.
4. **Суворий ліміт розміру правил (< 12,000 символів)**:
   - Жоден файл `.agents/rules/*.md` не може перевищувати 12,000 символів (жорсткий ліміт IDE).
   - При досягненні 11,000 символів проводиться модульне винесення в окремий `.md` файл.

- [ ] Перевірено розміри всіх rule-файлів: `for f in .agents/rules/*.md; do wc -m "$f"; done`

- [ ] Оновлено згадки в індексних файлах `AGENTS.md` та `agents_*.md`
- [ ] Запущено збірку спільних контрактів: `pnpm --filter @smartfeed/shared build`
