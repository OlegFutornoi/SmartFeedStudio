# Internationalization (i18n) Invariants

## I18N-01: 100% Bilingual Parity (UK ⇄ EN)

- Every user-visible string must have an identical key defined in both `locales/uk/*.json` and `locales/en/*.json`.
- Never commit keys to one dictionary without immediately adding the translation to the counterpart dictionary.
- Verify dictionary parity using `pnpm i18n:check`.
- Reason: Missing keys display raw fallback strings or crash rendering in the un-translated language.

## I18N-02: Zero Raw Untranslated Keys in UI

- Raw translation keys (e.g. `common:edit`, `suppliers:empty_title`) must never appear in rendered UI screens.
- Every label, button, placeholder, error message, toast, and dialog title must use `t('namespace:key')`.
- Reason: Raw keys exposed to end-users destroy perceived enterprise software quality.

## I18N-03: Translated HTML Attributes

- Tooltips, HTML titles (`title={t('...')}`), and accessibility labels (`aria-label={t('...')}`) must be dynamically localized.
- Never hardcode English strings in element attributes (`title="Edit"`, `aria-label="Delete"`).
- Reason: Hardcoded attribute strings leak English tooltips into Ukrainian interfaces when users hover over icon buttons.

## I18N-04: Backend Error Response Mapping

- API error responses must be intercepted and translated using `getErrorMessage(err, t)`.
- Never pass raw English server exception messages directly into client toast notifications.
- Reason: Unmapped backend exceptions expose technical English error strings and internal stack details to end users.

## I18N-05: Zero English Enums in UI Tables

- In Ukrainian locale, status badges and table cells must never display raw English backend enums (`APPROVED`, `Active`, `Done`, `Suspended`, `DECLINED`, `PENDING`).
- Map backend enums to localized display strings (`Оплачено`, `Активна`, `Виконано`, `Призупинено`, `Очікує`).
- Reason: Raw database enums in user tables break UI localization consistency.

## I18N-06: Clean Numeric Metric Formatting

- Numerical metrics such as percentages must be cleanly formatted (`Math.round(percent)` or `percent.toFixed(1)`).
- Never render raw unrounded floating-point calculations (e.g. `33.33333333333333%`).
- Reason: Unformatted raw floating-point numbers look broken and distort data table column layouts.
