# 📋 Задача QA-BE-01: Тестування реєстрації користувачів, видачі ліцензій та перевірка ізоляції даних (Multi-Tenancy / BOLA)

> **Префікс / ID:** `qa-be-01`  
> **Статус:** 🟡 В роботі (Active) — 25.10.2026  
> **Відповідальний агент:** `@agents_qa`  
> **Напрямок:** `Server / Backend` (`e2e/server/backend/`)  
> **Цільове середовище:** Ізольований тестовий контур (NestJS API `http://localhost:4001/api`, PostgreSQL `localhost:5433/smartfeed_test_db`, Mailpit `http://localhost:8025`)

---

## 1. Мета та контекст

Реалізувати набір типізованих API-тестів для перевірки життєвого циклу реєстрації нових користувачів, автоматичного створення персональних організацій, автогенерації ліцензій `STARTER` та жорсткої ізоляції даних між різними тенантами (захист від BOLA/IDOR).

Тести виконуються виключно в ізольованому контурі на порту `4001` проти RAM-бази даних на порту `5433`, без впливу на середовище розробки `smartfeed_db` (`:5432` / `:4000`).

---

## 2. Сценарії тестування

### 2.1. Реєстрація користувача (`POST /api/auth/register`)

- [ ] **TC-BE-01-01**: Успішна реєстрація нового користувача з валідними даними (email, пароль, ім'я).
  - Очікуваний результат: статус `201 Created`, повертаються `accessToken`, `refreshToken`, об'єкт `user` з роллю `USER`.
- [ ] **TC-BE-01-02**: Валідація некоректного email (невірний формат).
  - Очікуваний результат: статус `400 Bad Request` з інформативним текстом помилки.
- [ ] **TC-BE-01-03**: Спроба повторної реєстрації з тим самим email (дублікат).
  - Очікуваний результат: статус `409 Conflict` (або `400 Bad Request`), база не створює дублікатів.
- [ ] **TC-BE-01-04**: Валідація слабкого пароля (< 8 символів або без обов'язкових вимог).
  - Очікуваний результат: статус `400 Bad Request`.

### 2.2. Автоматичне створення організації та ліцензії

- [ ] **TC-BE-01-05**: Автоматичне створення персональної організації для щойно зареєстрованого користувача.
  - Очікуваний результат: `GET /api/organizations/my` повертає організацію, де користувач має роль `OWNER`.
- [ ] **TC-BE-01-06**: Автоматичне призначення безкоштовного тарифного плану `STARTER` та генерація ліцензійного ключа.
  - Очікуваний результат: `GET /api/licenses/my` повертає активну ліцензію з `planType = "STARTER"` та форматованим ключем `SF-STARTER-XXXX-XXXX-XXXX`.

### 2.3. Перевірка листів через Mailpit REST API

- [ ] **TC-BE-01-07**: Відправка привітального або верифікаційного листа на Mailpit.
  - Очікуваний результат: `GET http://localhost:8025/api/v2/messages` містить лист на email зареєстрованого користувача.

### 2.4. Ізоляція даних між тенантами (BOLA / Multi-Tenancy Protection)

- [ ] **TC-BE-01-08**: Спроба Користувача B прочитати профіль або ліцензію Користувача A.
  - Очікуваний результат: статус `403 Forbidden` або `404 Not Found`.
- [ ] **TC-BE-01-09**: Спроба Користувача B отримати доступ до постачальників чи товарів Користувача A.
  - Очікуваний результат: повертається лише власний список (довжина 0), чужі сутності не протікають.
