## 📌 1. Аналіз та Проблема

1. **Захаращеність таблиці («Колхоз»):**
   - Зараз всі користувачі (власники та запрошені) виводяться в один плоский перемішаний список, де для запрошених виводиться «Немає ліцензії» та дублюється «Власник: Тест Тестович» прямо в колонці організації.
   - Колонка «Квоти & Ліміти» перевантажує таблицю технічними цифрами, які вже доступні в ліцензіях та тарифах.
2. **Відсутність дій над користувачами:**
   - На відміну від сторінки Ліцензій, на сторінці Користувачів немає колонки Дій з 3 крапками (`...`) для швидкого призупинення (`isActive: false`) або видалення користувача.
3. **Масштабованість для великих команд:**
   - При наявності десятків або сотень співробітників в одній компанії плоский список стає нечитабельним. Потрібна ієрархічна структура: Власник як головний запис + вкладені рядки з можливістю згортання/розгортання + окрема модалка для перегляду та керування всією командою компанії.

## 🏛 2. Архітектурне Рішення

### 🗄 A. Модель даних та Бекенд CQRS (`services/backend-api`)

1. **Prisma Schema (`schema.prisma`)**:
   - Додати поле `isActive Boolean @default(true) @map("is_active")` до моделі `User`.
   - Додати складений індекс `@@index([role, isActive])` для оптимізованих запитів.
   - Виконати `pnpm --filter @smartfeed/backend-api exec prisma db push`.

2. **CQRS Команди та Ендпоінти (`UsersModule`)**:
   - `UpdateUserStatusCommand` -> `UpdateUserStatusHandler`:
     - Ендпоінт: `PATCH /api/users/:id/status` (Body: `{ isActive: boolean }`).
     - Оновлює статус користувача та синхронізує статус його персональної ліцензії.
   - `DeleteUserCommand` -> `DeleteUserHandler`:
     - Ендпоінт: `DELETE /api/users/:id`.
     - Безпечно видаляє користувача в каскадному порядку (з захистом від видалення суперадміна або власного акаунта адміністратора).
   - `GetUsersListQuery` -> `GetUsersListHandler`:
     - Ендпоінт: `GET /api/users`.
     - Збагачує об'єкт користувача полями `isActive: boolean`, `membersCount: number`, та масивом `teamMembers?: UserListItemDto[]` для швидкого інлайн-розгортання.

3. **Спільні DTO (`@smartfeed/shared`)**:
   - Оновити `UserListItemDto` з полями `isActive: boolean`, `membersCount: number`, `teamMembers?: UserListItemDto[]`.
   - Додати `UpdateUserStatusDto` (`isActive: z.boolean()`).

### 💻 B. Фронтенд Інтерфейс (`apps/admin-portal`)

1. **Очищення та структура колонок Таблиці (`UsersTable.tsx`)**:
   - **Користувач**: Аватар + Ім'я + Email + кнопка-шеврон `[▶ {count}]` / `[▼ {count}]` для компаній з командою.
   - **Роль**: Бейдж `👑 Власник` / `🛡 Адміністратор`.
   - **Компанія & Команда**: Назва компанії + клікабельний інтерактивний бейдж `👥 X співробітників` (відкриває модалку команди).
   - **Ліцензійний план**: Кольоровий бейдж тарифу (`STARTER`, `GROWTH`, `PRO`, `ENTERPRISE`).
   - **Статус**: Зелений / червоний бейдж `🟢 Активний` / `🔴 Призупинений`.
   - **Дата реєстрації**: Локалізована дата.
   - **Дії**: Меню 3 крапки (`...`) через `createPortal` (без обрізання таблицею).

2. **Інлайн Розгортання Підпунктів (`UserTeamSubRows.tsx`)**:
   - Клік на шеврон розгортає вкладені рядки запрошених співробітників безпосередньо під власником з м'якою анімацією та лінією зв'язку (`border-l-2 border-primary/40`).
   - Кожен співробітник має бейдж `👥 Запрошений`, статус, позначку `Успадковано ({Тариф})` та власне меню дій (`...`).

3. **Модальне вікно Керування Командою (`TeamMembersDialog.tsx`)**:
   - Відкривається при кліку на бейдж команди або з меню дій `👥 Переглянути команду`.
   - Містить список співробітників, їх контакти, статуси, дату приєднання, швидкі дії та лічильник квоти місць (`Зайнято X з Y місць`).

4. **Модальне вікно Підтвердження Видалення (`UserDeleteDialog.tsx`)**:
   - Модалка з попередженням про незворотність дії перед видаленням користувача.

5. **Меню Дій Користувача (`UserRowActions.tsx`)**:
   - Меню з фіксованим позиціонуванням у порталі:
     - `⏸ Призупинити` / `▶ Актувати`
     - `👥 Керувати командою` (для власників з командою)
