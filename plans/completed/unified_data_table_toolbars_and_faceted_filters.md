## 🔍 1. Інженерний аудит поточного стану (`agents_review`)

### Корінні причини розсинхронізації та відсутності єдиної системи компонентів:

1. **Ad-hoc створення тулбарів у різний час**:
   - `TransactionsFilterToolbar.tsx`: створений як окремий фільтр з великим інпутом (`w-full sm:w-[320px]`), громіздкою текстовою кнопкою `[🔄 Оновити]` та єдиним випадаючим списком `<Select>`.
   - `LicensesTableToolbar.tsx`: створений пізніше з використанням копіпасту `LicensesFacetedFilter`, компактним інпутом `w-64` та іконкою `[🔄]`.
   - `UsersTableToolbar.tsx`: використовував `FacetedFilter` з `ui/`, але містив лише 2 фільтри.
   - **Результат**: 3 різні таблиці мали 3 різні ширини пошуку, 2 різні стилі кнопки оновлення та 2 різні реалізації однакового дропдауну фільтрів (`faceted-filter.tsx` та дублікат `LicensesFacetedFilter.tsx`).

2. **Архітектурна ізоляція `DataTableViewOptions` у Транзакціях**:
   - У ліцензіях та користувачах кнопка `[Налаштувати стовпці]` вбудована безпосередньо в правий блок тулбара.
   - У `TransactionsTable.tsx` кнопка була винесена в окремий `<div>` між тулбаром і таблицею:  
     `<div className="flex items-center justify-end p-2.5 border-b border-border bg-card/40">`  
     Це візуально створило зайвий «поверх», розірвавши цілісність сторінки.

3. **Незбалансованість та зайві фільтри**:
   - **Ліцензії**: Фільтр «S3 Бекап» є суто технічним прапорцем ліцензії, яким ніхто не фільтрує у бізнес-сценаріях. Він перевантажує інтерфейс.
   - **Користувачі**: Відсутні базові фасетні фільтри за **Статусом** (`Активний` / `Призупинений`) та за **Тарифним планом** (`Free`, `Starter`, `Pro`, `Growth`, `Enterprise`), хоча ці поля є в кожній моделі користувача.
   - **Транзакції**: Відсутній фільтр за тарифом (`Plan`) та за платіжним шлюзом (`Gateway`).

## 🎨 2. Архітектурне бачення єдиної дизайн-системи (`agents_frontend`)

За зразком **NexaCRM People Template** та канонічних специфікацій `shadcn/ui`, кожен тулбар таблиці монорепозиторію SmartFeed Studio слідує **єдиній строгій анатомії**:

```text
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                              ЄДИНА АНАТОМІЯ DATA TABLE TOOLBAR (h-9)                                   │
├───────────────────────────────────────────────────────────────────┬────────────────────────────────────┤
│                    ЛІВА ЧАСТИНА (Фільтрація та пошук)              │     ПРАВА ЧАСТИНА (Дії та опції)   │
├─────────────────────────┬─────────────────────────┬───────────────┼─────────────┬───────────┬──────────┤
│    Уніфікований Пошук    │  Faceted Filters (x2-4) │  Скинути [↺]  │  Дія стор.  │ Стовпці   │ Оновити  │
│  w-full sm:w-64 (256px) │  border-dashed + badge  │ (якщо active) │ (CSV / +New)│ [Налаштувати] [ 🔄 ] │
└─────────────────────────┴─────────────────────────┴───────────────┴─────────────┴───────────┴──────────┘
```

### Стандартизовані інваріанти дизайн-системи:

1. **Висота контролів**: Строго `h-8` для компактного десктопного режиму та `h-9` для адмін-порталу.
2. **Пошуковий інпут**:
   - Фіксована адаптивна ширина: `w-full sm:w-64 max-w-xs`.
   - Іконка `Search` ліворуч (`size-3.5`).
   - Кнопка очищення `X` праворуч при наявності тексту.
3. **Faceted Filter (єдиний компонент `FacetedFilter`)**:
   - Стиль: `variant="outline"`, `border-dashed`.
   - Іконка домену + назва категорії (`Тариф`, `Статус`, `Роль`).
   - При виборі значення: вертикальний роздільник `|` та компактний `Badge` (`variant="secondary"`).
   - Ліквідація дубліката `LicensesFacetedFilter.tsx` на користь єдиного `@/components/ui/faceted-filter`.
4. **Праве крило дій**:
   - Кнопка дії сторінки (якщо є): `[Експорт CSV]` або `[+ Створити користувача]`.
   - `[Налаштувати стовпці]` (`DataTableViewOptions`) — завжди знаходиться на одній лінії всередині тулбара.
   - `[🔄]` — **строго іконка без тексту** (`h-8 w-8` або `h-9 w-9`, `p-0`, `title={t('common:refresh')}`, анімація `animate-spin` при завантаженні).
