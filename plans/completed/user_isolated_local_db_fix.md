# 📋 План: Ізоляція локальної БД (Web/Mock) за User ID та скидання стану при реєстрації

> **Статус:** ✅ **Реалізовано та протестовано (100% тестів пройдено)**  
> **Дата виконання:** 02.10.2026  
> **Мета:** Усунути проблему появи чужих або застарілих даних (постачальників, фідів, товарів) при реєстрації нового користувача у веб-режимі (`localhost:1420`).

---

## 🔍 Опис проблеми та коренева причина

1. У браузерному режимі (`http://localhost:1420`, `isTauri() === false`) клієнт використовує `mockDatabaseDriver`, який зберігав стан у `localStorage` під єдиним глобальним ключем `smartfeed_mock_db`.
2. При реєстрації або виході користувача цей ключ не очищався і не прив'язувався до конкретного `userId`.
3. В результаті новозареєстрований користувач (`dgo@gmail.com`) отримував дані постачальника з попередньої сесії (`AKS-01`), яка також вичерпувала квоту 1/1 безкоштовного тарифу «Старт».
4. У базі даних (як PostgreSQL, так і нативній SQLite в Tauri) цього запису не було, оскільки в браузері запити йшли виключно у веб-драйвер `localStorage`.

---

## 🛠 Реалізовані зміни

### Етап 1: Динамічний ключ сховища та очищення legacy-даних

- У файлі `apps/desktop/src/services/local-db/mock/mock-storage.ts`:
  - Додано функцію `getStorageKey(userId?: string | null): string`, яка повертає `smartfeed_mock_db_${userId}` (або `smartfeed_mock_db_guest`).
  - Додано функцію `clearLegacyMockDbStorage()`, яка очищає застарілий глобальний ключ `smartfeed_mock_db` при завантаженні та збереженні.
  - Збереження даних тепер ведеться в ізольованому ключі поточного користувача.

### Етап 2: Підтримка зміни користувача в `MockDatabaseDriver`

- У файлі `apps/desktop/src/services/local-db/mock-driver.ts`:
  - Додано відстеження `currentUserId: string | null`.
  - Реалізовано метод `switchUser(userId: string | null): void`.
  - При переході на новий `userId`, якщо збережених даних для нього немає — драйвер ініціалізує повністю чистий стан (`createInitialState()`).

### Етап 3: Інтеграція в `AuthContext`

- У файлі `apps/desktop/src/contexts/AuthContext.tsx`:
  - Під час `register()`: викликається `mockDatabaseDriver.switchUser(userProfile.id)` та емітується `emitDataSync` для негайного оновлення списків і квот (новий акаунт стартує з 0 постачальниками).
  - Під час `login()`: викликається `mockDatabaseDriver.switchUser(userProfile.id)`.
  - Під час `logout()`: викликається `mockDatabaseDriver.switchUser(null)` і скидається стан драйвера.
  - Під час ініціалізації: синхронізується драйвер із відновленим профілем користувача.

### Етап 4: Верифікація
