## 📌 1. Мета та контекст проблеми

Користувач на Кроці 3 («Попередній перегляд та вибір категорій») майстра імпорту бачить таблицю перших 5 товарів (`sampleProducts`). Раніше колонка «ФОТО» містила порожні квадратні рамки без жодного візуального розуміння: чи фото завантажуються, чи є помилка, чи вони взагалі підтягнулися з фіду.

### 🎯 Вимоги користувача:

1. **Миттєва доступність фото для прев'ю**: Для перших 5 товарів прев'ю їхні зображення мають завантажитися одразу під час аналізу/перегляду, щоб користувач міг їх бачити і оцінити якість каталогу.
2. **Фонова синхронізація для решти каталогу**: Всі інші фотографії (сотні або тисячі SKU) повинні завантажуватися пізніше у фоні (під час і після імпорту), не гальмуючи інтерфейс.
3. **Мінімалістичний та інформативний фідбек**: Користувач повинен чітко бачити стан завантаження фотографій (пульсуючий скелетон при завантаженні, елегантний статус-бейдж над таблицею, плавний fade-in при готовності, модальне збільшення при кліку).

## 🏛 2. Архітектура та 4-рівнева модель захисту (Defense-in-Depth)

```mermaid
graph TD
    A[XML / CSV Фід з посиланнями на фото] --> B[Етап 1: Аналіз фіду stream-parser]
    B --> C[Етап 3: Перші 5 товарів sampleProducts]
    C --> D[Компонент PreviewProductImage]
    D -->|1. Скелетон + Loader| E[Мінімалістичний індикатор завантаження]
    D -->|2. Прямий fetch / Proxy fallback| F[Кешування та перевірка]
    F -->|3. Успіх| G[Плавний fade-in фото + бейдж 'Готово']
    F -->|4. CORS / Помилка URL| H[Охайний Fallback ImageOff + тултип]
    C --> I[Мінімалістичний статус-бейдж над таблицею]
    I --> J['Фото прев'ю готові (5/5) • решта у фоні']
    K[Крок 4: Розпочати імпорт] --> L[Фонова черга завантаження решти фото каталогу]
```

### 1. Рівень 1 (Контракти & Типізація):

- Використання типізованих об'єктів `sampleProducts` з `images: Array<{ originalUrl: string; isMain?: boolean }>`.
- Чіткі статуси стану для кожного прев'ю фото: `'IDLE' | 'LOADING' | 'READY' | 'ERROR'`.

### 2. Рівень 2 (Стійкість завантаження & CORS Fallback):

- Якщо прямий URL фото блокується браузером через CORS/Mixed Content (HTTP посилання), компонент автоматично пробує `/feed-proxy?url=...`.
- В нативному режимі Tauri — задіюється локальний кеш або перевірка через Rust.

### 3. Рівень 3 (Бюджет модульності компонентів < 250 рядків):

- Розвантаження монолітного `WizardStepPreview.tsx`:
  - Винесення таблиці товарів у `WizardSampleProductsTable.tsx` (178 рядків).
  - Окремий мінімалістичний компонент для осередку фото: `PreviewProductImage.tsx` (98 рядків).
  - Модальне вікно перегляду збільшеного фото: `PreviewImageModal.tsx` (76 рядків).
- Сам `WizardStepPreview.tsx` скорочено до 275 рядків.

### 4. Рівень 4 (Edge Cases & Failure Modes):

- Фід взагалі не містить фотографій: показується елегантний бейдж `Фото відсутні у фіді` і fallback-іконка замість порожніх білих блоків.
- Помилка мережі: замість зникнення фото показується іконка `ImageOff` з тултипом причини.
